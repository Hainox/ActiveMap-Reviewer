## [2.0.0] — 2026-07-06

### Добавлено

- **Просмотр фото в сплит-режиме**: увеличенное фото теперь открывается в левой половине экрана вместо полноэкранного окна поверх всего. Правая половина остаётся полностью рабочей — видна карточка задания, список всех фото, кнопки решений — можно переключать фото и принимать решение (`1`–`9`, `S`/`Ы`), не закрывая увеличенный снимок
- Миниатюра текущего показанного фото подсвечивается в списке
- Настройки (фильтры и кнопки решений) сохраняются в `localStorage` и восстанавливаются при следующем запуске
- Автоматическая постраничная загрузка заданий свыше 500 (без предупреждения о лимите)
- Экспорт результатов сессии в CSV (номер задания, решение, статус, стадия, время)
- Кнопки решений блокируются на время отправки PATCH — исключает повторную отправку
- Структурированное логирование в `reviewer.log` рядом с .exe
- UX-обработка таймаута авторизации и прозрачная передача кода ошибки PATCH от ActiveMap
- Отладочные эндпоинты `/debug` и `/debug-task` доступны только при `DEBUG=1`
- Toast-уведомления и модалка подтверждения вместо системных `alert()`/`confirm()`
- Проверка автоматически сохраняется в `sessionStorage` — при случайной перезагрузке страницы (F5) после логина предлагается продолжить с того же места
- Отмена последнего решения по `Backspace` — не нужно открывать «Историю», чтобы исправить случайный клик
- Именованные пресеты фильтров (сохранить несколько наборов «Вид работы + Этап + Стадия + Организация», переключаться между ними)
- Статистика скорости («заданий/мин») на экране итогов
- Пометка «👥 Решено другим сотрудником» — при «Обновить» задания, статус которых сменился без вашего участия, помечаются визуально (список общий для нескольких сотрудников)

### Изменено

- ~20 глобальных JS-переменных объединены в объекты `AppState` и `LightboxState`
- `reviewer_html.html` разбит на именованные секции (`STATE`, `UI`, `API`, `LIGHTBOX`, `SUBMIT`)
- Все `.catch(function(){})` заменены на обработчики с логированием и уведомлением пользователя

### Исправлено

Найдено и исправлено многоагентным аудитом с состязательной проверкой каждого замечания:

- **Безопасность:** локальный прокси отправлял `Access-Control-Allow-Origin: *` на все ответы, включая авторизованные `/proxy/*` и `/patch/*` — любой сторонний сайт, открытый в том же браузере, мог читать и изменять задания через `localhost:8765`. Заголовок убран, он и не был нужен (фронтенд и бэкенд — один и тот же origin)
- `/debug` больше не отдаёт токен авторизации в открытом виде
- Гонка при повторном логине: медленный поток определения формата авторизации от старого входа мог перезаписать `auth_config` после более нового логина — добавлен счётчик поколений (`auth_epoch`), устаревший результат отбрасывается
- Таймаут ожидания авторизации (12 сек) отделён от обычного таймаута ответа сервера ActiveMap — раньше оба варианта тайм-аута логировались и показывались пользователю как «проблема авторизации», хотя чаще это просто медленный ответ сервера
- Каждая проба формата авторизации логируется при неудаче вместо молчаливого поглощения любой ошибки
- `_proxy_get` мог отправить второй HTTP-статус поверх уже отправленного при обрыве чтения ответа от ActiveMap — теперь тело читается до отправки заголовков
- «🔄 Обновить» обещал сохранить историю решений в диалоге подтверждения, но тут же обнулял её — теперь решения действительно сохраняются
- «🔄 Обновить» больше не обрезал список заданий до 500 без явного предупреждения пользователю — теперь использует ту же постраничную загрузку, что и первичный запуск проверки; эта же постраничная загрузка теперь не проглатывает HTTP-ошибки (401/503 и т.п.) как «заданий не найдено»
- Кнопки решений: подобранный по названию статус только визуально выглядел выбранным, но не сохранялся — из-за этого обе кнопки по умолчанию могли молча пропасть при нажатии «Начать проверку»; возврат в «⚙ Настройки» после этого не пересобирал экран настройки кнопок, из-за чего правки могли молча не сохраняться
- Восстановление сохранённого статуса-фильтра при устаревшем/удалённом ID больше не откатывается на произвольный первый статус в списке
- Экспорт CSV: добавлена колонка «Статус отправки» (Отправлено/Ошибка/В очереди) — раньше успешные, неотправленные и ожидающие решения было невозможно отличить в выгрузке
- `build.bat`: сборка больше не может молча оставить старый .exe в `dist\`, если новый файл не удалось переместить (например, из-за блокировки антивирусом)
- Два теста проверяли не то, что заявляли (совпадение по регулярному выражению уходило на тысячи символов в несвязанный код) — переписаны на точную проверку нужного участка

- Стадия карточки в фильтре настройки теперь обязательна (нет автовыбора «В работе»)

## [1.0.0] — 2026-06-15

Первый стабильный релиз.

### Добавлено

- Авторизация по логину/паролю ActiveMap (автодетект формата токена)
- Фильтрация заданий: вид работы, этап (статус), стадия (В работе / Завершено)
- Фильтр по организации/подрядчику
- Фильтр по периоду (дата от/до)
- Просмотр фотографий с лайтбоксом (до 15 фото)
- Кастомные поля задания с читаемыми названиями
- Настраиваемые кнопки решений (до 5 кнопок) с привязкой к статусам
- Горячие клавиши: `1`–`9` (решение + автопереход), `S`/`Ы` (пропуск), `←`/`→` (навигация)
- История решений текущей сессии с переходом по клику
- Фоновая очередь отправки статусов (PATCH в ActiveMap)
- Повторная отправка ошибочных заданий
- Кнопка «🔄 Обновить» — перезагрузить список без выхода из просмотра
- Форма отчёта об ошибках (🐛) с сохранением в `bug_reports.jsonl`
- Номер задания (#XXXXX) в заголовке карточки
- Версия приложения на экране входа
- Предупреждение при достижении лимита 500 заданий

### Исправлено

- Фотографии не загружались из-за некорректного определения поля-счётчика (`num_main_photo` — это индекс, а не количество)
- Кнопка «Пропустить» работала только один раз
- Задания со статусом «Завершено» попадали в список (добавлен фильтр по стадии)
- Кастомные поля показывали UUID-ключи и `[object Object]`
- Смена решения после успешной отправки не запускала повторный PATCH
